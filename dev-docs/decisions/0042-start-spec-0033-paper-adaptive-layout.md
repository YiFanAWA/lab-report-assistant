# 决策 0042：启动 SPEC 0033 论文级自适应版式

## 决策

确认实施 SPEC 0033，采用“共享语义规划器 + PPT/Word 薄渲染适配”的主线，不回档已有 PPT/Word 改进。

## 原因

当前问题是版式策略过于单一，而不是数据、图表、执行记录或文件生成链路失效。回档会丢失现有的可编辑 PPT、图表美化、来源追溯和真实渲染验收成果，不能解决版式缺少语义变化的问题。

## 约束

- `layout_planner.py` 是章节版式语义唯一 owner。
- `PptRenderer` 继续优先使用现有 `pptxforge`，只替换内容布局选择；python-pptx 保留为降级路径。
- `WordRenderer` 继续使用现有 DOCX 模板和默认渲染入口，只根据计划切换正文/步骤/结果样式。
- 不改 API、Worker、数据库 schema、LLM provider 合同和执行产物格式。
- 不新增依赖；使用已存在的 `pptxforge`、`python-docx` 和现有图表产物。

## 验收

以 SPEC 0033 中的六类语义版式、三套真实 PPT 工作流、Word/PDF 逐页渲染和全量回归为准。工具或环境自身导致的验收缺口必须记录，不能伪装成通过。
