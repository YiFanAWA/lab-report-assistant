# 决策 0048：启动 SPEC 0039 论文级多语义图形系统

**日期：** 2026-08-12  
**状态：** 已确认进入实现并完成实现，待项目负责人确认收口

## 背景

SPEC 0037 已经让数据图根据数据语义选择，但正式论文还需要研究框架、技术路线、样本筛选、变量关系和证据链等非传统图形。当前 `chart_planner.py` 只覆盖统计图，`layout_planner.py` 只覆盖章节版式，继续把逻辑图判断分散到 Word/PPT renderer 会产生重复语义和不可追溯的临时布局。

## 决策

接受以“共享 `FigurePlan` + 多语义图形规划器 + Word/PDF 与 PPT 薄适配”为唯一推荐路线，新增 SPEC 0039 设计范围：

- `server/app/modules/outlines/figure_planner.py` 作为图形语义唯一 owner；
- `chart_planner.py` 保留数据图选择能力，作为 `data_chart` 子适配器；
- 逻辑图由已确认大纲、证据、分析方案和执行产物产生，不从模型临时文本创造事实；
- Word/PDF 与 PPT 消费同一 `FigurePlan`，论文侧重完整题注与追溯，PPT 侧重单页主结论；
- 复用现有 `pptxforge` 组件和已有图表/渲染依赖，不复制外部模板，不新增运行时依赖；
- 首个案例至少增加研究证据链、数据处理管线和变量关系/研究框架三类逻辑图，同时保留现有统计图；
- 因果边必须有明确依据，观察性关联必须显式标注，未知关系安全降级。

## 不变项

- 不修改数据库 schema、API、LLM Gateway、Worker 和项目产品边界；
- 不做 L3 完整论文复现，不提供医学诊疗建议；
- 不把所有内容统一画成树状图，也不为了数量重复生成图形；
- 不进入自由拖拽式工作流或外部图形渲染服务；
- SPEC 0038 的正式论文结构、引用、参考文献、题注和三线表继续作为既有规范。

## 实施闸

已按“合同/测试 → 规划器 → 案例产物 → Word/PDF/PPT 适配 → 真实视觉验收”的顺序完成实现：新增共享 `FigurePlan` 语义合同和选择器，案例生成研究证据链、数据处理管线、变量关系三类逻辑图，Word/PDF 与 PPT 均消费同一份图形元数据；全量后端回归 `1167 passed`，真实 Word/PDF 与 PowerPoint 页面检查通过。

## 停止条件

首个案例生成至少 3 张语义不同的逻辑图，Word/PDF/PPT 均从同一 `FigurePlan` 消费，真实文件视觉检查通过，全量后端回归无新增失败，并由项目负责人确认图形语义和论文效果后收口。
