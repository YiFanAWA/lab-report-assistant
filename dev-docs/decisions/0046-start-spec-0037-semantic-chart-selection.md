# 决策 0046：启动 SPEC 0037 语义图表选择与 PPT 组件优化

**日期：** 2026-08-12  
**状态：** 已按项目负责人确认实施

## 决策

接受 SPEC 0037，采用“图表语义规划器 + 案例真实绘图 + 现有 PPT 组件组合”的单一路线。

## 原因

当前问题不是数据不足，而是案例脚本把不同分析目的统一交给柱状图函数，导致图表同质化；PPT 组件已经存在，主要缺口是页面角色没有消费这些组件。

## 约束

- 图表选择必须服务数据表达，不以增加图形数量为目标；
- Word/PPT 继续来自同一份大纲和执行 artifact；
- 只复用已安装的 `pptxforge` 和现有工作流，不复制外部仓库资源；
- 不新增运行时依赖，不改变 API、数据库和模型合同；
- 统计结果仍是公开 CSV 的教学性复核，不包装成论文原始模型复现。

## 验收证据

- 图表规划定向测试通过；
- 重新生成案例得到六类以上真实图形，并在 `analysis_summary.json` 保存规划理由；
- 两套 PPT 重新生成且 `pptxforge` 不触发溢出降级；
- 标准 PPT 逐页渲染工具受本机依赖缺失阻断，保留替代验证与环境缺口记录。
