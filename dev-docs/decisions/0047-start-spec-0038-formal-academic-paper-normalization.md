# 决策 0047：启动 SPEC 0038 正式学术论文规范化改造

**日期：** 2026-08-12  
**状态：** 已按项目负责人确认实施

## 决策

接受 SPEC 0038，采用“正式论文结构规划器 + `formal_academic` Word renderer profile + 真实来源/图表题注元数据”的单一路线。

## 原因

当前交付物的数据量和图表类型已经足够，主要欠缺不再是内容数量，而是学术文档的规范合同：前置部分、章节层级、文内引用、参考文献、题注和表格样式没有形成统一真源。

## 约束

- Word/PDF 继续从已确认大纲、真实执行产物和来源目录生成；不在 renderer 内创造统计事实。
- 引用只指向已确认论文和数据集来源；不生成虚构参考文献。
- 继续区分原论文样本与本地公开 CSV 复核口径，不包装成完整原模型复现。
- 不新增运行时依赖，不改变 API、数据库 schema、LLM 模型合同和 PPT 组件路线。

## 验收证据

- 正式 DOCX 可重开并通过结构 QA。
- Word 通过真实 Office 发布流程导出 15 页 PDF。
- PDF 逐页渲染检查封面、摘要、结果图表、森林图与三线表、参考文献和附录，未发现裁切、溢出或字体丢失。
- 定向测试、全量后端测试和生成脚本均通过。
