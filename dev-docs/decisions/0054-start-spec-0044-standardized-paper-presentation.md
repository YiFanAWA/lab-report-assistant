# 决策 0054：启动 SPEC 0044 标准化论文成品展示与排版

**日期：** 2026-08-14  
**状态：** 已确认进入 SPEC 编写；SPEC 0044 仍待项目负责人确认后才能实现  
**关联 SPEC：** SPEC 0043 论文出版级结构、排版与交付物统一系统  
**关联审查：** `dev-docs/paper-quality-review-spec0043-2026-08-14.md`

## 1. 用户确认的产品目标

论文生成结果必须从：

> AI 工作流和工程追溯的展示

改成：

> 读者看到的是一篇格式规范、排版统一、图表和文字部署自然的论文成品。

这次目标的重点是标准化论文展示、图表部署和 Word/PDF 格式，不是继续增加 AI 解释、图表类型、MCP 工具或工程审计内容。

## 2. 决策内容

- 先编写并确认 SPEC 0044，再修改 `ManuscriptPlan -> WordRenderer`；
- `ManuscriptPlan` 继续作为论文语义和正文投影的 owner；
- `PublicationProfile` 继续作为版式 profile 的单一合同，不在 renderer 内散落新的格式常量；
- Word renderer 只消费读者正文投影和版式 profile，不拥有研究结论和资产选择；
- 工程追溯信息继续保留，但默认转移到 manifest、审计附件或显式技术附录；
- DOCX 仍是唯一排版真源，PDF 仍只由最终 DOCX 导出；
- MCP 安装包和新增图表类型暂不作为当前优先级。

## 3. 本次不做的事情

- 不在 SPEC 0044 确认前修改 `document_planner.py`、`word_renderer.py` 或 `docx_pdf_exporter.py`；
- 不改变数据分析、统计结果、证据卡片、LLM Gateway 或数据库 schema；
- 不新增学校/期刊专用模板承诺；
- 不把内部审计信息删除或丢失；
- 不用装饰性 icon、彩色卡片或压缩字体替代论文的规范排版。

## 4. 进入实现的前置条件

项目负责人需要确认 SPEC 0044 中的以下产品可见合同：

1. 正文默认不显示工程追溯字段；
2. 采用通用中文学术论文 profile，而不是宣称某个学校或期刊官方格式；
3. 图题在图下、表题在表上，图表编号和交叉引用由 Word 动态字段维护；
4. 正式论文 profile 默认使用黑色正文、统一字体和三线表语义；
5. 真实 Diabetes 案例通过正文泄漏检查、Word 字段结构检查和逐页视觉验收。

在以上合同确认前，当前切片停止在 SPEC 文档阶段，不进入代码实现，也不推进 MCP 或图表扩展。
