# SPEC 0038：正式学术论文规范化改造

**状态：** 实现完成，待项目负责人确认收口  
**日期：** 2026-08-12  
**前序 SPEC：** SPEC 0037 语义图表选择与论文级 PPT 组件优化  
**owner：** `server/app/modules/outlines/document_planner.py` 负责正式论文结构与引用计划；`word_renderer.py` 负责 DOCX 版式呈现；案例生成脚本负责把真实来源、统计结果和图表题注写入交付物。

## 1. 问题

前序版本已经具备较大样本、真实图表和论文解读内容，但 Word/PDF 仍更接近“格式较好的实验报告”：章节命名、文内引用、参考文献、图表题注、表格规范和前置部分不够接近正式学术论文。

## 2. 目标

1. 将 Word/PDF 交付物规范化为 A4 正式论文结构：封面、摘要、关键词、目录、章节编号、参考文献和附录。
2. 让正文引用与参考文献表由同一份来源目录规划，引用编号按首次出现顺序稳定生成。
3. 让真实图表具备章节化图号、中文题名和数据口径说明；CSV 结果表采用论文式三线表。
4. 保留原论文与本地复核的边界说明，不把教学性复核包装成原论文模型的完整复现。
5. 保持 Word/PDF 与 PPT 继续消费同一份已确认大纲、执行产物和来源信息。

## 3. 规范化规则

### 3.1 论文结构

- 一级章节采用“第 N 章”格式：绪论、研究背景与资料来源、数据来源与研究对象、研究设计与统计方法、结果、讨论/局限性/结论。
- 二级章节采用“5.1”形式；前置部分包含摘要、关键词和目录。
- 封面包含正式题名、副标题、研究类型、研究对象、数据边界、执行批次和教学性免责声明。

### 3.2 引用与参考文献

- 仅对来源目录中已确认的来源生成 `[n]` 引用。
- 编号按大纲中来源首次出现顺序生成；同一来源重复出现时复用编号。
- 参考文献至少保留论文 DOI 或数据集 DOI；来源不足时显式说明，不生成虚构文献。

### 3.3 图表与表格

- 图表题注采用“图 5-1”或“表 5-1”章节编号。
- 题注下方保留数据口径、复核边界或来源说明。
- 正式 profile 下 CSV 表使用无彩色填充、上下粗线与中间细线的三线表风格。
- 图表内容继续复用 SPEC 0037 的语义图表选择，不为了论文外观强行改变图表类型。

## 4. 实现范围

- 扩展 `ThesisDocumentPlan`，增加正式标题、元数据、引用映射和正式章节名称。
- 扩展 `WordRenderer` 的 `formal_academic` profile，统一封面、前置部分、章节编号、引用、参考文献、题注和三线表。
- 更新 `generate_spec0035_paper_review.py`，为真实论文、UCI 数据集、真实图表和结果表提供来源/题注元数据。
- 新增规划器与渲染器契约测试；不改变 API、数据库 schema、LLM Gateway、Worker 和运行时依赖。

## 5. 完成标准

- 正式 DOCX 可重新打开，包含摘要、关键词、目录、6 个论文一级章节、正文引用、参考文献和附录。
- 真实案例生成 15 页 PDF，封面、摘要、结果图表、森林图/三线表、参考文献和附录视觉检查通过。
- 论文 PDF 使用 A4 页面，图表无裁切、表格无溢出、页眉页脚与页码连续。
- 定向测试和全量后端测试通过；无新增运行时依赖。

## 6. 边界与未做事项

- 本 SPEC 只规范 Word/PDF 论文交付物；不把 PPT 改造成论文页面，也不引入新的 PPT 模板资源。
- 不做原论文 L3 完整模型复现，不提供医学诊疗建议。
- 不自动爬取受限数据库；案例来源仍限于公开可访问论文、数据集页面和本地已确认文件。
