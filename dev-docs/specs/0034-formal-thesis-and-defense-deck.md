# SPEC 0034：正式论文 Word/PDF 与高级答辩 PPT

## 1. 背景与问题

SPEC 0033 已将章节语义与版式规划从固定双栏中抽离，但当前交付物仍更接近“论文式实验报告 + 简洁学术 PPT”。项目负责人希望形成两条明确成品线：

1. Word/PDF：可以直接作为正式论文式实验报告阅读和打印；
2. PPT：可以用于正式学术汇报或答辩，而不是把 Word 段落简单分页。

本切片不回档，不重写数据、证据、执行和大纲链路，只补齐交付物层的结构、版式和叙事表达。

## 2. 目标

### 2.1 正式论文 Word/PDF

- 使用 A4 纵向页面、稳定页边距和统一中英文字体层级；
- 生成封面、中文摘要、关键词、目录、正文、结论/局限、参考资料和附录；
- 使用真实 Heading 样式和稳定章节编号，支持目录更新和章节导航；
- 为图、表、执行产物建立连续编号、题注、来源和必要的正文交叉引用；
- 对宽图表或宽表格使用受控横向节，不压缩正文，不让内容溢出；
- 统一页眉、页脚、页码、章节起始和分页规则；
- DOCX 作为可编辑源，PDF 由同一 DOCX 渲染链导出，不另写一套内容生成逻辑。

### 2.2 高级答辩 PPT

- 保留 16:9、可编辑 PPTX、真实执行图表和现有主题系统；
- 采用“研究问题 → 数据与方法 → 关键结果 → 解释与局限 → 结论”的答辩叙事；
- 每页只保留一个主要表达任务和一个核心结论，标题优先写成可口头表达的结论句；
- 为研究问题、方法流程、关键指标、单图结论、多图比较、局限与结论分别设计版式；
- 减少重复卡片、标签和无意义装饰，避免把长段落塞进 PPT；
- 对每张结果图保留图名、单位、样本/口径和来源信息；
- 在生成后检查文字溢出、图表裁切、页间节奏、标题换行和页码连续性。

## 3. 非目标

- 不改变实验数据、图表数值、执行记录、证据来源或已确认大纲；
- 不由 LLM 重新编造论文结论、引用或实验结果；
- 不承诺某一所学校的完全合规格式。学校特定格式需要用户提供官方规范或模板后，另设适配切片；
- 不引入在线模板市场、校园账号、外部图片下载或新的运行时依赖；
- 不删除 `native_editable` 降级路径和既有 PPT/Word API 合同。

## 4. Owner 与调用链

共享语义继续由 `server/app/modules/outlines/layout_planner.py` 负责；本切片新增的正式论文与答辩叙事结构由同一交付物规划层承载，Word/PDF/PPT 渲染器只负责呈现。

推荐调用链：

```text
已确认大纲 + 执行产物 + 图表索引
  -> 交付物结构规划器
  -> ThesisDocumentPlan / DefenseDeckPlan
  -> WordRenderer -> DOCX -> PDF
  -> PptRenderer -> PPTX
```

API、前端、Worker、LLM prompt 和临时预览脚本不得复制论文目录、答辩章节或图表编号规则。

## 5. 推荐文档结构

### 5.1 Word/PDF

```text
封面
摘要
关键词
目录
第 1 章 绪论/实验要求
第 2 章 数据与资料
第 3 章 方法与分析流程
第 4 章 结果
第 5 章 讨论、局限与结论
参考资料
附录：执行产物与追溯索引
```

如果已确认大纲没有完整的绪论或讨论内容，规划器只组织已有内容，并以“未提供/未执行”结构化提示占位，不补造事实。

### 5.2 PPT

```text
标题页
汇报问题与目标
数据与方法
分析流程
关键结果 1
关键结果 2 / 对比结果
结果解释与局限
结论与可复核证据
```

页数由 `target_slide_count` 约束，优先保证内容完整和视觉可读，不为了凑页数复制内容。

## 6. 版式合同

| 对象 | 规则 |
|---|---|
| 正文 | 正文样式、首行缩进、固定行距和段后间距统一，不使用散落直接格式化作为主规则 |
| 章节 | Heading 1/2/3 具备真实层级，编号由统一规则生成 |
| 图 | `图 4-1` 或连续编号二选一，由文档规划器统一；图题、来源和图体保持相邻 |
| 表 | `表 4-1` 或连续编号二选一；列宽、表头重复和跨页规则显式设置 |
| 来源 | 执行产物来源可追溯到 artifact/run；外部资料只使用已有证据卡片 |
| PPT 标题 | 默认不少于 35pt；标题不得意外换行，必要时先改写标题或版式 |
| PPT 正文 | 默认不少于 16pt；先减少内容或换布局，再考虑缩小字号 |
| PDF | 必须由最终 DOCX 导出并逐页渲染检查，不能只通过文本抽取判断 |

## 7. 依赖与环境边界

- 优先复用现有 `python-docx`、`pptxforge`、图表产物和 PPT/PDF 渲染工具链；
- 不新增运行时依赖，除非实现中证明现有工具无法满足且另行登记依赖决策；
- DOCX/PDF 视觉验收依赖 LibreOffice 或 Word 可用。若当前环境缺失，必须完成结构验收并明确记录视觉验收缺口，不得宣称 PDF 已通过视觉验收；
- PPT 必须渲染全部页面并逐页检查，同时运行溢出检测。

## 8. 验收标准

### A. 文档结构

- DOCX 包含封面、摘要/关键词、目录、正文、参考资料或参考资料缺失提示、附录；
- Heading 层级和章节编号稳定，图表题注编号不重复；
- 图表、来源、执行产物和 run 追溯关系仍然存在；
- 宽图表/宽表格不会溢出正文区域。

### B. PPT 叙事与视觉

- 真实样例包含标题、问题、方法、结果、局限、结论六类叙事节点；
- 每页有单一主结论，标题和图表含义一致；
- 所有页面通过渲染、逐页检查和溢出检测；
- 至少检查一个数据概览页、一个方法页、一个单图结果页、一个多图对比页和结论页。

### C. 回归门禁

- 相关 Word/PPT/布局规划测试通过；
- 全量后端测试、Alembic、前端 lint/build 通过；
- DOCX 渲染 PNG 和 PDF（环境支持时）逐页检查；
- PPTX 渲染全部页面并检查无裁切、重叠、文字截断和图表错配；
- `dev-docs/acceptance.md`、依赖审查和 `dev-docs/README.md` 完成回写。

## 9. 停止条件

正式论文 Word/PDF 和高级答辩 PPT 均能从同一份已确认大纲与执行产物生成，结构、编号、来源和视觉验收门禁闭合后，本 SPEC 收口。学校特定封面、页边距、字体、参考文献格式和章节命名不纳入本轮，等待官方模板或规范后再单独适配。
