# SPEC 0044：标准化论文成品展示与排版

**状态：** 实现完成，待项目负责人确认收口
**日期：** 2026-08-14
**前置 SPEC：** SPEC 0043“论文出版级结构、排版与交付物统一系统”
**产品目标：** 把论文生成结果从“AI 工作流和工程追溯的展示”，改成“读者看到的是一篇格式规范、排版统一、图表和文字部署自然的论文成品”。

## 1. 背景与问题

当前 `ManuscriptPlan`、`PublicationProfile` 和 Word renderer 已经具备正式论文的章节、动态字段、图表编号和 PDF 导出基础，但真实成品仍把内部生产语义暴露给论文读者：

- 正文出现 `Artifact Source`、`Figure Lead`、`CHART_PNG` 等工程字段；
- 图表附近出现“主张 / 方法 / 结果 / 边界”“stages -> nodes -> transitions”等内部规划表达；
- 普通 CSV 执行产物可能直接进入正文表格，带有工程化的“前 N 行、前 M 列”说明；
- 正式论文样式仍混有蓝色标题、彩色表头、审计说明和重复性模板段落；
- 图、表、正文、图题、表题和解释段落的空间关系没有收敛为一个稳定的读者阅读规则。

这不是继续增加图表类型或继续扩充 AI 文案的问题，而是“论文正文投影”和“Word 版式合同”没有彻底分离。

## 2. 目标

本切片只解决标准化论文成品的展示层：

1. 论文正文只面向读者，不展示 AI 工作流、资产生产过程和内部审计字段；
2. 建立一个可重复的中文学术论文通用版式 profile；
3. 统一正文、标题、图、表、图题、表题、页眉、页脚、目录和参考文献的部署规则；
4. 保留真实来源、样本量、统计口径和解释边界，但以自然论文语言呈现；
5. 让 DOCX 成为唯一排版真源，PDF 继续由最终 DOCX 导出；
6. 用真实 Diabetes 案例完成结构检查和逐页视觉验收。

## 3. 非目标与边界

- 不新增 MCP、Skill、远程服务或安装包能力；
- 不新增图表类型、科研图形资产或 PPT 组件；
- 不改变数据集、分析执行、统计结果、证据卡片或原论文内容；
- 不把本项目包装成某所学校或某个期刊的官方模板；
- 不维护第二套 PDF 正文排版；
- 不删除审计信息，只把审计信息从默认论文正文移到 manifest、结构化审计附件或显式技术附录；
- 不用缩小字体、堆叠卡片、增加装饰图形或增加泛化段落来掩盖正文内容不足；
- 不改变 `ManuscriptPlan` 的业务 owner，不让 Word renderer、API、UI 或 MCP 重新拥有论文语义。

## 4. Owner 与调用边界

### 4.1 唯一 owner

- `server/app/modules/outlines/document_planner.py`：拥有论文角色、章节顺序、读者可见内容、`PublicationProfile` 和正文/审计投影边界；
- `server/app/modules/outlines/figure_planner.py`：拥有图形的语义、图题所需的读者信息和图表与章节的关联；
- `server/app/infrastructure/renderers/word_renderer.py`：只把已确认的论文计划和 profile 转成 DOCX；不决定研究结论和图表是否应该存在；
- `server/app/infrastructure/documents/docx_pdf_exporter.py`：只负责最终 DOCX 到 PDF 的适配，不重新排版正文。

### 4.2 禁止成为 owner 的层

API、前端、Worker、MCP、LLM prompt、临时脚本和 `execution_artifacts` 列表都不能私自决定：

- 哪些内容进入论文正文；
- 图表在论文中的章节位置；
- 论文标题层级和编号；
- 论文的版式 profile；
- 来源、执行记录和资产信息是否对读者可见。

## 5. 正文投影合同

### 5.1 两种输出面

同一份已确认事实必须产生两个隔离的投影：

```text
ManuscriptPlan
  ├─ ReaderPaperProjection -> DOCX/PDF 正文
  └─ AuditProjection -> manifest / 审计附件 / 显式技术附录
```

默认 `ReaderPaperProjection` 只输出标题、摘要、关键词、章节正文、读者需要的图表、图表说明、参考文献和必要附录。

### 5.2 正文禁止出现的内容

默认论文正文不得出现以下内部字段、资产类型和流水线表达：

- `Artifact Source`、`Figure Lead`、`CHART_PNG`、`TABLE_CSV`；
- asset ID、SHA-256、JSON 路径、执行批次 ID、内部文件名；
- `stages -> nodes -> transitions` 等图表生成语法；
- “主张 / 方法 / 结果 / 边界”内部模板标签；
- “本报告的第一项任务 / 第二项任务”这类重复的生产过程说明；
- 仅为了证明系统可追溯而放入正文的资产清单和运行日志。

来源、样本、方法和限制只有在属于论文读者需要的信息时，才改写成自然的学术句子保留。

### 5.3 正文图表来源

图表来源只保留读者需要的来源、数据集、样本范围、单位和统计说明。若图表没有足够的读者可读语义，不能直接把原始执行产物截图或 CSV 前几行当作论文图表；应进入审计附件，或由已有的语义图表计划生成正式图表。

## 6. 通用学术版式合同

第一版使用项目自有的通用中文学术论文 profile，不声称满足具体学校或期刊模板。所有值必须由 `PublicationProfile` 统一提供，禁止散落在 renderer 方法中。

### 6.1 页面与字体

- A4 纵向；
- 页面边距沿用并显式固化现有论文 token：左/右 2.4 cm，上/下 2.2 cm；
- 中文正文使用宋体，英文和数字使用 Times New Roman；
- 正文 10.5 pt，1.5 倍行距，首行缩进 2 个中文字符，两端对齐；
- 正文颜色为黑色或接近黑色；正式论文 profile 不使用蓝色标题、彩色卡片或彩色表头作为视觉主元素；
- 图题、表题和必要注释使用统一的小字号和黑/灰色，不通过颜色表达业务状态。

### 6.2 标题层级

- 封面标题居中、黑色、加粗；
- 一级章节标题使用稳定的多级编号，黑色、加粗，章节开始时遵循统一分页规则；
- 二级、三级标题左对齐，标题与后续正文保持在同一阅读块中；
- 标题不能孤立在页底；标题编号由 Word numbering 合同生成，不手工拼接重复编号；
- 目录使用章节/小节书签和 PAGEREF 生成紧凑入口，避免导出器更新动态 TOC 后产生孤立空白页。

### 6.3 页眉、页脚和页码

- 封面、摘要、目录、正文、参考文献和附录使用明确的 section；
- 前置部分使用罗马数字，正文使用阿拉伯数字；
- 页眉页脚只保留论文标题、章节信息和页码等读者需要的信息；
- 不在页眉页脚显示资产 ID、运行批次或内部系统名称；
- 页码由 Word 字段生成，PDF 由最终 DOCX 导出后验证。

## 7. 图、表与文字部署合同

### 7.1 正文阅读节奏

正文采用以下自然阅读顺序：

```text
段落提出问题或结果
  -> 图 / 表
  -> 标准图题 / 表题
  -> 正文解释与统计边界
```

图表不作为独立的资产清单出现。图表前后的文字必须服务于论文论证，不重复解释内部生成过程。

### 7.2 图部署

- 图放置在首次正文引用之后或最接近的位置；
- 图与图题保持在同一分页块内，优先避免图题单独落页；
- 图题放在图下，采用动态 `SEQ Figure`；
- 图宽不超过正文可用宽度，保持原始比例，不拉伸变形；
- 图中必须有可读的标题、坐标轴、单位、图例或必要注释；
- 图中不使用与论文无关的装饰性 icon；科研示意图的线宽、字体和颜色保持同一 profile；
- 正文交叉引用使用 `REF/PAGEREF`，不静态写死页码；
- 图题不出现 asset ID、内部文件名和生产阶段。

### 7.3 表部署

- 表题放在表上，采用动态 `SEQ Table`；
- 表格优先使用三线表语义，不使用彩色卡片、斑马纹或产品化表头；
- 表头与数据保持可读字号，长表允许分页但必须重复表头；
- 表格不能被截断为“前 10 行、前 6 列”后直接冒充完整结果表；
- 若只展示摘要统计，必须在表题或注释中说明统计范围、单位和样本量；
- 表格不能在正文中附带内部资产索引或生成日志。

### 7.4 段落与分页

- 正文段落不出现孤行、寡行和大面积不必要空白；
- 标题、图题、表题与对应内容使用 `keep_with_next` 或等价的 Word 段落合同；
- 章节、图表和附录的分页由 renderer 统一控制，不在正文内容中硬编码分页符；
- 正文不因为塞入追溯说明而被迫产生单独的“工程说明页”。

## 8. 参考文献与交叉引用

- 正文引用、参考文献编号和目录使用同一份 `ManuscriptPlan`；
- 参考文献只输出真实、可核验的来源，不为了视觉完整而生成虚假引用；
- 参考文献使用统一缩进、行距和编号；
- 缺少真实来源时，内容门禁返回缺口，不用“来源待补”占位句伪装成正式参考文献。

## 9. 实现顺序（确认后执行）

1. 扩展现有 `PublicationProfile`，集中承载版式 token、正文可见性和图表部署规则；
2. 在 `document_planner.py` 中形成读者正文投影，过滤工程追溯字段；
3. 在 `word_renderer.py` 中消费 profile，统一标题、段落、图表、表格、section 和动态字段；
4. 保持 `docx_pdf_exporter.py` 只做最终 DOCX→PDF 转换；
5. 添加正文泄漏负向测试、Word 字段结构测试、图表分页合同测试和真实案例 fixture；
6. 使用 Diabetes 案例生成 DOCX/PDF，进行结构检查和逐页视觉验收；
7. 文档、验收记录和真源索引同步回写。

## 10. 验收标准

### 10.1 结构验收

- 正文不包含 `Artifact Source`、`Figure Lead`、`CHART_PNG`、`TABLE_CSV`、asset ID、SHA、JSON 路径和执行批次字段；
- 正文章节只按论文语义组织，不按 `source_type`、资产类型或执行阶段组织；
- DOCX 包含紧凑目录条目、SEQ Figure/Table、REF/PAGEREF、多级标题编号、section 和两套页码字段。
- 图题在图下、表题在表上，编号不重复，正文引用指向对应对象；
- 正文不直接渲染原始 CSV 前几行作为正式结果表；
- 正式论文 profile 不产生彩色卡片化正文和工程资产索引页。

### 10.2 真实案例验收

使用现有 Diabetes 论文案例生成一套 DOCX/PDF，至少包含摘要、目录、五章、核心图表、参考文献和必要附录，并确认内容事实与现有分析产物一致。

### 10.3 视觉验收

DOCX→PDF 后逐页检查：

- 页面尺寸、边距、字体、行距和缩进一致；
- 标题不孤立，图表不裁切、不重叠、不变形；
- 图题、表题、表头和注释可读；
- 目录、页码和交叉引用与最终页码一致；
- 没有因工程追溯信息产生的空白页、拥挤页或异常分页；
- 论文整体呈现为传统学术文档，而不是 PPT、产品报告或 AI 过程记录。

## 11. 最大回归风险与停止条件

最大回归风险是：为了隐藏工程字段而误删来源、样本、统计口径或限制信息，导致论文失去可验证性。因此所有过滤必须发生在“正文投影”层，不能删除 `ManuscriptPlan` 或审计投影中的事实。

出现以下任一情况时停止收口：

- 正文仍需要显示 asset ID、执行日志或内部模板字段才能解释图表；
- 图表只能靠缩小字体或强行压缩内容才能塞入页面；
- Word/PDF 出现两套不同排版真相；
- 真实案例无法通过正文泄漏检查或逐页视觉检查；
- 内容门禁、Word 字段、PDF 转换或文档索引未形成当前证据。

只有在 SPEC 0044 合同确认、共享 owner 链闭合、真实案例通过结构和逐页视觉验收、文档同步完成后，才允许将该切片收口。
