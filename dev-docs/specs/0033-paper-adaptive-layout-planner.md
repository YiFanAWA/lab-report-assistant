# SPEC 0033：论文级自适应版式与语义布局规划器

## 1. 背景

现有 Word/PPT 已能保持数据、图表、执行记录和确认大纲的一致性，但 PPT 内容页主要使用固定双栏结构，Word 章节也主要使用统一段落样式。结果是交付物稳定，却缺少论文汇报所需的内容层次和版式变化。

本切片不回档、不删除已有渲染器能力，新增一个共享的语义布局规划器，让交付物先根据大纲章节语义、文字密度和图表数量生成版式计划，再由 PPT/Word 渲染器分别呈现。

## 2. 目标

- 为同一份已确认大纲生成稳定、可解释的章节级版式计划。
- PPT 根据章节语义选择不同构图：叙事页、数据概览页、方法步骤页、单图重点页、多图对比页、总结页。
- Word 根据同一版式计划选择正文、方法步骤、结果章节和总结章节的呈现方式。
- 保留 PPTX 可编辑、Word/PDF 可导出、图表来源和执行批次追溯能力。
- 默认将前端 PPT 生成入口切换到 `academic` 自适应模式；后端未指定工作流时保持兼容的 `native_editable` 默认。

## 3. 非目标

- 不修改大纲、证据、数据集、执行或交付物数据库合同。
- 不让模型、前端或临时脚本决定版式语义；规划器是唯一 owner。
- 不引入在线模板市场、校园账号、外部图像下载或新的运行时依赖。
- 不把正文硬编码成固定论文内容；规划器只决定结构，不改写实验事实。
- 不删除原有 python-pptx 降级路径。

## 4. Owner 与调用链

唯一 owner：`server/app/modules/outlines/layout_planner.py`。

调用链：

```text
已确认大纲 + 执行产物
  -> layout_planner 生成 SectionLayoutPlan
  -> PptRenderer 选择 pptxforge 版式原语
  -> WordRenderer 选择段落/步骤/结果呈现方式
  -> Word/PPT/PDF 真实渲染验收
```

API、前端、Worker、LLM prompt 和具体渲染器不得复制章节语义判断。

## 5. 版式语义

规划器输出以下 `layout_kind`：

| 版式 | 适用章节 | PPT 构图 | Word 呈现 |
|---|---|---|---|
| `narrative` | REQUIREMENT、EVIDENCE 或普通正文 | 低密度叙事/重点说明 | 普通正文段落 |
| `data_overview` | DATASET 且可提取至少两个指标 | 指标行 + 数据说明 | 数据概览段落 |
| `method_flow` | ANALYSIS 且有多个步骤 | 方法步骤横向节奏 | 编号步骤段落 |
| `result_focus` | EXECUTION 且只有一张图 | 半幅大图 + 结果解释 | 结果正文 + 单图 |
| `result_compare` | EXECUTION 且有两张及以上图 | 多图对比/图表组 | 结果正文 + 图表组 |
| `summary` | SUMMARY | 总结强调语 | 结论段落 |

规划优先级：章节 `source_type` > 图表数量 > 内容密度。图表只从真实执行产物中关联，不生成假指标。

## 6. 验收标准

- 规划器对六类标准章节产生预期 `layout_kind`。
- 短正文不会被强行塞入双栏；方法章节不再被当作普通正文；单图结果页使用重点构图；多图结果页使用对比构图。
- 既有无配置 API 调用仍使用 `native_editable`，现有测试和旧降级方法保持可用。
- 前端默认工作流为 `academic`，用户仍可切换 `native_editable` 与 `sjtu_academic`。
- 真实样例 PPTX、DOCX、PDF 可重新打开并逐页渲染；无文本裁切、图表重叠、页脚覆盖、空白异常或图表错配。
- 后端测试、Alembic、前端 lint/build 全部通过。

## 7. 停止条件

当规划器单元测试、PPT/Word 定向测试、真实样例渲染和全量项目门禁均通过，本 SPEC 收口。若视觉问题来自图表本身的数据或字体，不在本切片中重写数据执行链路。
