# SPEC 0039：论文级多语义图形系统

**状态：** 已实现，待项目负责人确认收口  
**日期：** 2026-08-12  
**前序 SPEC：** SPEC 0038 正式学术论文规范化改造  
**owner：** `server/app/modules/outlines/figure_planner.py` 负责论文图形语义、选择规则、节点/边合同和追溯关系；`chart_planner.py` 作为数据图形适配器复用已有统计图选择逻辑；Word/PDF 与 PPT renderer 只消费 `FigurePlan` 并负责格式呈现。

## 1. 问题

SPEC 0037 已经解决了“不同数据使用不同统计图”的问题，但当前论文图形仍主要由执行产物驱动：只要有 PNG 或 CSV，就倾向于安排数据图。正式论文还需要表达研究逻辑、方法路径、变量关系和证据边界，例如：

- 研究问题如何进入研究设计；
- 样本怎样筛选并形成最终分析队列；
- 变量、结局和控制因素怎样组织；
- 原论文证据、本地数据和复核结论怎样连接；
- 数据怎样经过清洗、分析和验证后形成结果。

这些内容不能用柱状图、树状图或装饰性流程图替代。系统需要先判断内容的语义，再选择“数据图、流程图、概念框架图、关系图、证据链图或机制路径图”。

## 2. 目标

1. 建立统一的论文图形语义合同，覆盖数据、流程、关系、机制、证据和结构六类表达。
2. 让规划器根据已确认大纲、证据卡片、数据分析方案和真实执行产物选择图形，不根据“图形越多越好”或 renderer 的临时判断选图。
3. 支持正式论文中常见的非传统数据图：研究框架图、研究技术路线图、样本筛选流程图、变量关系图、观察性关系 DAG、证据链图、数据处理管线图、时间线和机制路径图。
4. 复用项目已有 `pptxforge` 的 `Stack`、`TwoColumn`、`Grid`、`IconRow`、`Callout` 等组件；不复制 `ppt-master`、上海交大模板、字体或图片资源。
5. Word/PDF 与 PPT 使用同一份 `FigurePlan`，但允许不同 renderer 采用不同呈现密度：论文侧完整题注、图注和来源，PPT 侧突出主线和可读性。
6. 对因果关系保持证据边界：没有明确研究设计或用户确认的因果关系，不得绘制为确定性因果箭头。

## 3. 非目标与边界

- 不把所有章节都改成逻辑图；有真实数值比较时，仍优先使用合适的统计图。
- 不默认使用树状图。树形结构仅用于真实的层级、分类或目录关系；流程、证据链和变量关系不得套用树状图。
- 不从模型临时生成事实、节点、边、变量含义或因果结论。节点和边必须来自已确认大纲、来源、分析方案或执行记录。
- 不做原论文 L3 完整模型复现，不把观察性关联写成诊断、治疗或确定性因果结论。
- 不新增数据库表、API 字段、LLM Gateway 合同或前端自由拖拽式图形编辑器。
- 不引入新的图形运行时依赖；本切片默认复用现有 Python 标准库、`matplotlib`、`python-docx`、`python-pptx` 和已批准的 `pptxforge`。
- 不在本切片内重做论文正文、参考文献体系或 PPT 主题系统；这些能力分别由 SPEC 0038、SPEC 0030/0032 负责。

## 4. 语义分类与选择规则

### 4.1 图形语义类别

| 语义类别 | 适用问题 | 首选图形 | 禁止替代 |
|---|---|---|---|
| `data_chart` | 数值大小、分布、比较、不确定性和趋势 | 横向条形图、构成图、Dumbbell、点估计+区间、趋势图、森林图 | 用流程图表达数值大小 |
| `research_framework` | 研究问题、变量、假设和分析路径的总体结构 | 概念框架图 | 把所有章节堆成树 |
| `process_flow` | 方法步骤、样本筛选、数据处理阶段 | 流程图、技术路线图 | 用柱状图表达步骤 |
| `relationship_graph` | 变量、证据或对象之间的非因果关系 | 关系图、概念网络图 | 无依据的因果箭头 |
| `causal_dag` | 明确的暴露—结局—混杂因素结构 | DAG | 将相关关系标为因果 |
| `evidence_chain` | 来源、数据、复核和结论之间的证据链 | 证据链图 | 用来源列表代替逻辑关系 |
| `data_pipeline` | 原始数据到结果产物的处理路径 | 数据管线图 | 把执行产物平铺为图库 |
| `mechanism_path` | 已有证据支持的机制或解释路径 | 机制路径图 | 编造医学机制 |
| `timeline` | 事件、时间点、随访或研究阶段的先后关系 | 时间线 | 无时间语义的装饰线 |
| `hierarchy` | 真实分类、层级或目录关系 | 层级图 | 把流程和证据链画成树 |

### 4.2 决策优先级

规划器按以下顺序判断：

1. **显式语义优先：** 大纲或分析方案若明确声明 `figure_intent`，直接进入相应语义校验。
2. **来源结构推断：** `source_type`、`source_ids`、证据卡片类型和执行产物关系只能补充候选，不能凭空创造结论。
3. **数值语义判断：** 仅在存在可核验数值、比较、排序、区间或自然顺序时调用 `chart_planner`。
4. **安全降级：** 语义不足时保留正文或使用最小信息图，不强行生成图形；不得回退成无理由树状图。
5. **去重与密度控制：** 同一章节最多一个主逻辑图；同一关系不得同时生成概念框架图、DAG 和机制图，除非大纲明确要求并且证据边界不同。

### 4.3 因果和观察性关系约束

- 只有在研究设计、用户确认的假设或来源明确支持时，边才可标记为 `causal`。
- 仅有相关性、组间差异或回归关联时，边必须标记为 `associational`，图注中写明“观察性关联，不代表因果关系”。
- 未知、待确认或超范围关系不得渲染为实线确定箭头；可在计划中保留为 `uncertain` 并降级为正文提示。
- 论文解读案例中的“原论文结论”和“本地描述性复核”必须使用不同节点样式或分组，禁止合并为单一证据源。

## 5. 共享图形合同

实现时新增 `FigurePlan` 及相关不可变结构，最小字段如下：

```text
FigurePlan
  figure_kind: FigureKind
  semantic_role: str
  title: str
  nodes: tuple[FigureNode, ...]
  edges: tuple[FigureEdge, ...]
  data_artifact_ids: tuple[str, ...]
  source_ids: tuple[str, ...]
  execution_run_ids: tuple[str, ...]
  caption: str
  note: str
  rationale: str
  editable_preference: "native" | "vector" | "raster"
  target_surfaces: tuple["word", "ppt"]
```

其中：

- `FigureNode` 至少包含稳定 id、显示标签、节点角色和证据状态；
- `FigureEdge` 至少包含起点、终点、关系类型、标签和证据状态；
- 节点和边引用不存在的 id 时，规划器必须拒绝该计划；
- `source_ids`、`execution_run_ids` 和 `data_artifact_ids` 允许为空，但不能用虚构 id 占位；
- `rationale` 必须说明为什么选择该语义图，以及为什么没有选择传统数据图；
- `caption` 和 `note` 由规划器或已确认案例元数据提供，renderer 不得自行补写统计事实。

`chart_planner.ChartPlan` 继续作为 `data_chart` 的统计图子计划；它不再承担流程、关系、证据和机制图的语义判断。

## 6. 交付物适配

### 6.1 Word/PDF

- 逻辑图与数据图均按章节自动编号，沿用 SPEC 0038 的“图 N-M”题注规则。
- 图下必须包含题注、数据/证据口径和必要的非因果说明。
- 优先使用矢量或高 DPI 图形；若采用 PNG，必须保留源图形计划和稳定执行产物索引。
- 论文侧显示完整节点标签、关系说明、来源和限制，不压缩为 PPT 式短句。
- 图形无法安全容纳时，降级为分步小图或正文表格，不允许裁切、重叠和文字缩小到不可读。

### 6.2 PPT

- 方法、证据链和研究框架优先使用现有 `pptxforge` 组件组合：`IconRow` 表达线性阶段，`TwoColumn` 表达两类证据或变量组，`Grid` 表达并列关系，`Callout` 强调关键边界，`Stack` 组织标题/图形/结论。
- 图形必须服务于一页一个主结论；不把论文整页截图塞进 PPT。
- 逻辑图与统计图使用同一 `FigurePlan` 的标题、来源和边界信息，但允许 PPT 采用摘要式题注。
- 概念框架、DAG 和证据链不得默认全部排成树状结构；布局由节点/边关系和页面密度决定。
- 本切片优先保障语义正确和可读性；完整的 PPT 原生连接线编辑能力不作为首期硬性目标，必要时使用可追溯的矢量/高 DPI 图形降级。

## 7. 首个案例的图形改造范围

基于 SPEC 0035/0037/0038 的 Diabetes 130-US Hospitals 论文解读案例，首期至少增加或升级以下逻辑图，不改变已有真实统计结果：

1. **研究证据链图：** 开放论文 → 数据集 → 本地 CSV 描述性复核 → 解释边界；区分原论文样本与本地公开数据口径。
2. **数据处理管线图：** 原始 CSV → 缺失结构检查 → HbA1c 分组 → 30 天再入院比较 → 简化模型/结果索引。
3. **研究框架或变量关系图：** HbA1c 检测状态、30 天再入院结局及已确认的分析变量；若没有足够证据，只表达“分析关系”，不表达确定因果。
4. **样本筛选流程图：** 复用已有真实样本计数和执行记录，不重新估算样本量。

现有的构成图、Dumbbell、点区间图、趋势图和森林图继续保留。首期不强行增加机制图；只有来源或用户确认的机制描述足够明确时才生成。

## 8. 实施阶段与验收

### 8.1 实施阶段

1. 在 `figure_planner.py` 建立 `FigureKind`、节点/边合同、语义选择器和引用校验。
2. 为现有 `chart_planner` 增加 `data_chart` 薄适配，不改变已确认统计图结果。
3. 更新 SPEC 0035 案例生成脚本，生成逻辑图元数据和真实图形产物。
4. 更新 Word/PDF renderer，复用题注、来源、章节编号和版式保护。
5. 更新 PPT renderer，复用现有 `pptxforge` 组件和既有工作流模式。
6. 运行定向测试、全量后端测试、真实 Word/PDF/PPT 生成和逐页视觉验收。

### 8.2 完成标准

- 规划器对 `data_chart`、`process_flow`、`research_framework`、`relationship_graph`、`evidence_chain` 和 `data_pipeline` 至少各有一个契约测试。
- 非法节点/边引用、无依据因果边、缺失追溯信息和未知语义均有拒绝或安全降级测试。
- 首个案例生成至少 3 张逻辑图，且与现有统计图语义不重复；不再默认把所有非数值内容画成树状图。
- Word/PDF 与 PPT 均消费同一份 `FigurePlan`；真实文件可重新打开，图题、来源和限制说明齐全。
- Word/PDF 逐页检查无裁切、重叠、不可读文本或题注错位；PPT 逐页检查无溢出、乱码、图形错配和过度拥挤。
- 现有 SPEC 0037 的 9 张语义图表、SPEC 0038 的 15 页正式论文结构和引用/表格规范零回归。
- 不新增运行时依赖，不修改数据库 schema、API、LLM Gateway、Worker 或项目产品边界。

## 9. 风险与停止条件

- **语义臆造风险：** 图形可能让观察性关联看起来像因果关系；通过 `causal/associational/uncertain` 边合同、题注和负向测试阻断。
- **图形泛滥风险：** 图形数量增加但论文逻辑变差；通过每章节主图上限、去重规则和真实案例人工视觉复核阻断。
- **布局风险：** 逻辑图节点和连接线比统计图更容易拥挤；无法满足可读性时必须降级为分步图或正文，不得缩小字体硬塞。
- **追溯断裂风险：** 逻辑图可能没有单一数据文件；仍必须保存来源 id、执行 run id 或已确认大纲来源，拿不到证据就显示不可用原因。

当首个案例的 3 张逻辑图完成生成、Word/PDF/PPT 真实视觉验收通过、全量回归无新增失败，且项目负责人确认图形语义符合预期时，SPEC 0039 才可收口。

## 10. 明确不进入本切片的内容

- 自由拖拽式图形编辑器；
- 任意 Mermaid/Graphviz 在线服务或外部渲染服务；
- 让大模型直接输出未经校验的 SVG、PPT XML 或连接线坐标；
- 自动推断医学机制、诊疗路径或因果结论；
- 用装饰性图标、渐变和阴影替代研究关系；
- 为了“看起来更丰富”重复生成统计图、流程图和树状图。
