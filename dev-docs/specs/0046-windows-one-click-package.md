# SPEC 0046：Windows 一键运行封装（已确认实现）

> 状态：已确认进入实现；本轮实现与验收材料已形成，待项目负责人确认版本收口。
> 本切片不改变实验报告助手的业务 API、数据库模型和分析合同。

## 1. 目标

将当前本地单用户 Web MVP 封装为 Windows x64 用户可直接下载和运行的发布包：用户不需要安装 Docker、Python、Node.js，不需要创建虚拟环境、执行命令或编辑 `.env` 文件，双击根目录的 `实验报告助手.exe` 后即可打开工作台。

第一版仍采用本机浏览器作为界面载体；“EXE”负责启动和管理本地服务，不把现有 React 页面重写成原生桌面 UI。

## 2. 用户可见结果

- 发布物为 Windows x64 portable bundle，根目录提供 `实验报告助手.exe` 启动器。
- 用户解压后双击启动器，程序自动启动后端 API、后台 Worker 和前端服务。
- 启动器等待 `/health` 通过后自动打开默认浏览器的本机工作台地址。
- 用户不需要看到或修改 Docker、Python、Node.js、npm、pip、SQLite 迁移和环境变量细节。
- 程序关闭时停止本轮启动的子进程；异常退出时保留可定位问题的本地日志。
- 项目数据库、数据集、模板和交付物写入用户可恢复的数据目录，不写入安装包自身的只读资源目录。

## 3. 推荐发布结构

```text
实验报告助手-win-x64/
├─ 实验报告助手.exe       # 用户唯一需要操作的入口
├─ service/                # PyInstaller one-directory 后端与 Worker 运行时
│  ├─ service.exe         # 后端或 Worker 入口
│  └─ sandbox_runner.exe  # 受控 Python 执行入口
├─ web/                    # React 生产构建产物
├─ README-使用说明.txt     # 最小故障排查说明
└─ release-manifest.json   # 文件哈希清单
```

发布包内部可以包含多个运行文件，但用户路径只暴露一个启动器。第一阶段优先验证 portable bundle；安装器、桌面快捷方式、代码签名和自动更新不作为本切片的必要条件。

## 4. 运行合同

### 4.1 启动器 owner

新增 Windows 分发适配层，负责：

- 解析发布包根目录和用户数据目录；
- 注入内部运行配置，不要求用户维护 `.env`；
- 启动后端和 Worker 子进程；
- 为本机服务选择可用的 loopback 端口；
- 轮询健康检查并限制启动等待时间；
- 打开浏览器、展示结构化启动失败信息、保存日志；
- 在退出时按确定顺序回收自己创建的子进程。

启动器不得拥有项目状态、实验状态、LLM 语义或文档生成语义；这些仍归现有后端 owner 层。启动器只做进程编排、路径映射和用户可见的运行状态投影。

### 4.2 前端服务

- 生产前端由 `apps/web` 的构建产物提供。
- 便携包不依赖开发服务器、Node.js 或 nginx 安装。
- `/api`、健康检查、SSE 和文件下载继续使用现有 API 合同。
- 前端 UI 后续可以继续修改；每次发布重新构建 `web/`，不改变用户数据目录。

### 4.3 后端与 Worker

- 后端与 Worker 使用发布包内置的 Python 运行时和依赖。
- 启动时自动执行 Alembic 迁移，迁移失败必须阻断启动并写入错误日志。
- 绑定 `127.0.0.1`，不默认暴露到局域网。
- 默认数据库和项目数据位置由启动器注入到用户数据目录。
- 不允许把用户数据写回发布包的源码、runtime 或 web 目录。

### 4.4 LLM 能力

- 无 API Key 时，基础工作流必须可以启动并使用本地规则提供者完成可用路径。
- 本切片不把 DeepSeek API Key 写入发布包、源码、日志或默认配置。
- DeepSeek 等外部模型的用户内配置入口作为后续设置切片；不能把“免环境配置”误写成“无需外部服务凭证即可获得联网模型能力”。

## 7. 验收门禁

### 7.1 构建验收

- 在开发机完成前端生产构建、后端依赖收集和启动器构建。
- 构建过程不读取用户本地 `.env` 中的真实密钥，不把 `node_modules`、`.venv`、测试数据和运行产物误打入发布包。
- 发布包 manifest 记录版本、目标平台、入口、运行时版本和文件哈希。

### 7.2 干净环境验收

在未安装 Python、Node.js、Docker 的 Windows x64 环境中：

1. 解压发布包；
2. 双击 `实验报告助手.exe`；
3. 浏览器自动打开并通过健康检查；
4. 创建项目、录入实验要求、上传数据集并完成一条最小分析路径；
5. 生成并下载 Word/PPT 交付物；
6. 关闭并重新启动程序，确认项目数据仍然存在；
7. 模拟端口占用和后端启动失败，确认用户获得可理解的错误与日志位置；
8. 关闭程序后确认启动器创建的子进程已回收。

### 7.3 停止条件

- 干净 Windows 环境可以完成上述主路径，且不需要用户安装任何开发运行时。
- 现有后端和前端回归测试通过。
- 发布包不含密钥、运行产物或未经许可的资源。
- 文档已写回 `dev-docs/` 和外部使用说明，并完成 Git 版本收口。

## 8. 已知风险

- pandas、NumPy、SciPy、scikit-learn、Matplotlib、resvg 等二进制依赖可能导致包体积较大，需要以真实构建结果确定体积预算。
- Windows Defender 或未签名 EXE 可能触发提示；本切片记录风险，暂不把购买代码签名证书作为阻断条件。
- Word/PDF/PPT 生成链必须在干净环境实际运行，不能只依据本机开发环境通过。
- 浏览器仍是运行时依赖；用户需要有可用的本机默认浏览器，但不需要安装项目专用浏览器。
