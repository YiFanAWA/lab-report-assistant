# SPEC 0041：论文级异构图形编排与语义选图系统

**状态：** 已确认进入实现并完成实现，待项目负责人确认收口  
**日期：** 2026-08-13  
**前序 SPEC：** SPEC 0040 期刊级论证图表与论文视觉语法改造  
**owner：** `server/app/modules/outlines/figure_planner.py` 继续拥有图形语义与编排合同；`chart_planner.py` 继续拥有数值图表选择；Word/PDF/PPT renderer 只做呈现适配。

## 1. 背景与问题

SPEC 0039 和 SPEC 0040 已经建立了多语义图形和论证图合同，但当前论文案例仍容易出现两类问题：

1. 复杂内容被压缩成同一种流程图、树状图或四面板证据链，图形形式与表达任务不匹配；
2. 图形数量增加了，但缺少“为什么此处用这种图、数据是否满足该图的前提、如果不满足应该拒绝什么”的编排规则。

正式论文并不是把所有内容都画成图，也不是追求图形种类越多越好。论文中的流程图、关系图、矩阵图、时间线、统计图、研究框架和论证图各自承担不同的阅读任务。SPEC 0041 要解决的是“同一份论文中，如何根据主张、数据结构和证据强度选择合适的视觉语法，并让整套图形形成有层次的组合”。

## 2. 目标

1. 在现有 `FigurePlan` 和 `ChartPlan` 之上增加论文级异构图形编排，不新建与 `figure_planner.py` 并行的语义 owner。
2. 让每个图形同时具备：表达任务、图形家族、数据前提、选择理由、来源/执行追溯和失败边界。
3. 让一套论文可以合理共存以下图形，而不是统一套用树状图或多面板框架：
   - 样本纳入与数据处理流程图；
   - 暴露—结局—协变量关系图或受限 DAG；
   - 论文样本与本地复核的比较矩阵/方法—证据矩阵；
   - 构成图、横向条形图、Dumbbell、点估计区间图、趋势图和森林图；
   - 时间线、研究框架、机制路径和证据论证图。
4. 对不满足数据或证据前提的图形显式拒绝或降级，不通过装饰性节点、虚构连接或伪造复杂度“补图”。
5. PPT 继续复用现有 `pptxforge` 主题、`Callout`、`Text`、`Image`、连接线、表格和布局组件；Word/PDF 继续保持正式论文的题注、来源、注释和章节编号。
6. 让论文案例至少展示五种不同图形家族，且每一种都能说明它解决了哪一个具体表达问题。

## 3. 非目标与边界

- 不做自由拖拽图形编辑器、手工设计软件或外部在线绘图服务。
- 不为了“图形多样性”强行加入没有数据支持的热力图、桑基图、网络图或机制图。
- 不把观察性关联自动升级为因果关系；`CAUSAL_DAG` 和 `MECHANISM_PATH` 仍必须满足现有来源/执行记录约束。
- 不做 L3 原论文完整模型复现，不补造原论文没有公开的数据字段或统计量。
- 不修改数据库 schema、API、LLM Gateway、Worker、产品边界和运行时依赖。
- 不让 PPT renderer 或生成脚本拥有研究结论、统计事实、因果判断或图形选择真相。

## 4. 设计合同

### 4.1 图形语义与视觉家族分层

`FigureKind` 表达“这张图在论文中是什么语义”，`FigureFamily` 表达“用哪种视觉语法呈现”。两者都由 `figure_planner.py` 统一管理，renderer 不自行推断。

建议的 `FigureFamily`：

| 图形家族 | 适合回答的问题 | 允许的典型形式 |
|---|---|---|
| `statistical` | 数值大小、构成、差异、不确定性和趋势是什么？ | 构成图、横向条形图、Dumbbell、点区间图、趋势图、森林图 |
| `process` | 样本如何筛选、数据如何处理、分析如何推进？ | 阶段流程图、数据管线、泳道式分析流程 |
| `relationship` | 哪些变量或概念有关联，角色如何分层？ | 观察性关系图、受限 DAG、变量角色图 |
| `matrix` | 多个对象在多个维度上如何对应或比较？ | 论文—本地比较矩阵、方法—证据矩阵、数据质量矩阵 |
| `evidence_argument` | 主张、证据、结果和边界如何组成论证？ | 证据链、多面板论证图、主张—证据—限制图 |
| `temporal` | 事件或研究阶段按什么时间顺序发生？ | 时间线、阶段序列、随时间变化的趋势图 |
| `structural` | 研究对象、章节或概念如何组织？ | 研究框架、分层结构、受控层级图 |
| `mechanism` | 已有来源支持的机制路径是什么？ | 机制路径图；必须标注假设/证据状态 |

`FigureKind` 的现有类型继续作为语义基础。若当前语义确实不存在（例如论文—本地多维比较矩阵），在实现阶段以最小扩展方式增加类型；不得在 renderer 中用字符串约定偷偷新增类型。

### 4.2 编排计划

在 `figure_planner.py` 内增加与现有 `FigurePlan` 同一 owner 下的论文级编排合同，建议包含：

```text
FigurePortfolioPlan
  figures: tuple[FigurePlan, ...]
  coverage: tuple[str, ...]
  selection_rationale: tuple[str, ...]
  rejected_candidates: tuple[RejectedFigureCandidate, ...]
```

每个 `FigurePlan` 增加或等价承载以下信息：

```text
visual_family: FigureFamily
layout_profile: str
data_requirements: tuple[str, ...]
selection_rationale: str
```

其中：

- `visual_family` 是呈现语法，不替代 `figure_kind`；
- `layout_profile` 只描述可复用的布局契约，如 `single_focus`、`flow_stages`、`matrix_grid`、`evidence_panels`、`relationship_layers`、`timeline_track`；
- `data_requirements` 是生成前可校验的前提，不是 renderer 的补丁条件；
- `selection_rationale` 必须说明“主张/数据结构 → 图形选择”的原因；
- `rejected_candidates` 记录被拒绝的候选及其原因，避免下游再次把不合适的图形生成出来。

### 4.3 语义选图规则

| 证据或数据语义 | 首选图形 | 不应使用 |
|---|---|---|
| 样本经过多个筛选阶段 | `process_flow` / `FLOW` | 用柱高表示筛选流程，或用树状图替代阶段转移 |
| 类别占总体比例 | `statistical` / `STACKED_COMPOSITION` | 用节点大小或无基准的气泡装饰 |
| 无自然顺序的类别排名 | `statistical` / `HORIZONTAL_BAR` | 旋转标签拥挤的竖向柱图 |
| 两个口径对同一对象的成对比较 | `statistical` / `DUMBBELL` | 两组不对齐的独立柱图 |
| 组间估计及置信区间 | `statistical` / `POINT_CI` | 只显示点估计而隐藏不确定性 |
| 有自然顺序的年龄、时间或等级 | `statistical` / `ORDERED_LINE` 或 `temporal` | 把有序水平当成无序类别 |
| 多变量调整效应 | `statistical` / `FOREST` | 用单一总分或装饰性雷达图替代模型结果 |
| 暴露、结局和协变量的观察性关联 | `relationship` | 没有因果证据却使用因果箭头 |
| 多对象 × 多维属性的对照 | `matrix` | 把二维对照强行画成树或线性流程 |
| 真实事件的时间先后 | `temporal` | 没有时间字段的伪时间线 |
| 主张、证据、结果和边界的组合 | `evidence_argument` | 把所有内容都包装成四面板图 |
| 有来源支持的机制假设 | `mechanism` | 无来源的自由联想机制图 |

规则优先级为：数据/证据前提 > 表达任务 > 版面可读性 > 视觉多样性。视觉多样性不能推翻前面三项。

### 4.4 前提校验与安全降级

至少实现以下校验：

- `matrix`：必须存在行维度、列维度和可追溯单元格值；缺少二维值时降级为正式表格或拒绝生成，不绘制空热力图。
- `temporal`：必须存在可排序的时间/阶段字段；只有叙述性“先后”时使用流程图，不伪造时间轴。
- `relationship`：必须存在有类型的节点和有语义的边；观察性边必须明确“非因果”。
- `CAUSAL_DAG`：继续要求已确认来源或执行记录支持因果边。
- `mechanism`：没有来源支持的路径标记为 `uncertain` 或拒绝进入正式论文图；不得用箭头暗示已证实机制。
- `process_flow`：必须存在阶段、转移或处理动作；没有阶段关系时不得回退成树状图。
- `evidence_argument`：继续满足 SPEC 0040 的 `ArgumentPlan`、证据层、结果和边界合同。
- 数值图表：继续由 `ChartPlan` 按数据类型、分析目的、顺序和不确定性选择；不能由“当前页面空白”触发默认柱图。

降级顺序固定为：同一语义下的更稳健图形 → 正式表格/文字说明 → 结构化不可用原因。禁止用不相干的图形填补空位。

## 5. 论文案例的目标图形组合

继续使用 Diabetes 130-US Hospitals 与 Strack 等 2014 年开放论文案例，但将整套成品编排为“语义互补”的图形组合。以下是目标组合，不代表每篇论文都必须固定生成全部图形：

| 建议顺序 | 论文问题 | 目标图形 | 真实前提 |
|---|---|---|---|
| Figure 1 | 研究问题、数据来源和分析范围是什么？ | 研究框架/范围图 | 有论文来源、数据来源和边界说明 |
| Figure 2 | 样本如何从公开记录进入本地复核？ | 样本流程图 | 有真实筛选阶段和计数 |
| Figure 3 | 数据质量问题集中在哪里？ | 缺失率横向条形图；有行列模式时才用质量矩阵 | 有字段级或行列级缺失统计 |
| Figure 4 | 论文口径与本地可复核口径如何对应？ | 论文—本地比较矩阵 | 有两套口径、指标和可比性说明 |
| Figure 5 | 原论文主张如何被来源、数据和本地结果支撑或限制？ | 多面板证据论证图 | 满足 `ArgumentPlan` 与 SPEC 0040 证据层合同 |
| Figure 6 | 论文结果与本地复核差异多大？ | Dumbbell 成对比较图 | 有成对估计值 |
| Figure 7 | 主要结果的不确定性如何？ | 点估计区间图或森林图 | 有估计值和区间；模型效应才使用森林图 |
| Figure 8 | 结果是否随有序分层变量变化？ | 趋势图或 small multiples | 有自然顺序和分组观测值 |
| Figure 9 | 变量在观察性分析中如何关联？ | 分层关系图 | 有暴露、结局、协变量角色；明确非因果 |

该组合的重点是“每张图回答不同问题”，而不是机械追求九张图。若真实数据不支持某一项，编排计划必须展示拒绝理由。

## 6. Word/PDF/PPT 呈现要求

### 6.1 Word/PDF

- 每张图保留章节编号题注、图形主张、来源、数据口径、方法和解释边界。
- 矩阵类内容优先使用正式三线表或矢量表格，避免缩小成不可读图片。
- 流程、关系、时间线和研究框架使用统一线宽、节点层级和注释规则，不套用统计图坐标轴。
- 统计图保留单位、样本量、区间定义和必要的图例；不得为了版面隐藏关键统计信息。
- A4 页面中图形按内容复杂度自适应，禁止通过统一固定高度导致关系图、矩阵图或长标签裁切。

### 6.2 PPT

- 每页明确一个可讲述主张；复杂图形占据页面主视觉区，说明文字只承担解释和边界提示。
- 流程图使用现有连接线与阶段组件；矩阵使用现有表格/文本组件；关系图使用分层节点和无交叉连接；统计图直接复用真实图表产物。
- 组件优先复用 `pptxforge` 现有主题、`Callout`、`Text`、`Image`、表格和布局原语，不新增一套孤立装饰组件。
- 不把不同语义的小图强行塞进同一四宫格；只有共享一个主张且各子图承担互补证据时才使用多面板。
- 需同时适配 `native_editable` 与 `sjtu_academic`，保持已有主题和字体回退规则。

## 7. 实施顺序

1. 先补 `FigureFamily`、`FigurePortfolioPlan` 或等价合同及其序列化/负向校验；不先改 renderer。
2. 在现有论文案例中补齐矩阵、研究框架或时间线等真实语义所需的数据投影；缺少数据时记录拒绝候选。
3. 将现有流程图、关系图、证据图和统计图迁移到编排计划，由同一计划驱动 Word/PDF/PPT。
4. 在 PPT 中为流程、矩阵、关系、时间线和论证图分别选择已有组件组合，避免 renderer 按文件名猜布局。
5. 运行定向测试、全量测试和真实文件渲染；逐页检查 Word/PDF/PPT 的裁切、重叠、标签可读性、线条交叉和图注追溯。
6. 更新 `dev-docs/acceptance.md`、`dev-docs/implementation-plan.md` 和本 SPEC 的实现记录后，等待项目负责人确认收口。

## 8. 验收标准

- `FigurePlan`/编排合同可以序列化到现有 artifact 元数据，并保留 `figure_kind`、`visual_family`、`layout_profile`、`data_requirements` 和选择理由。
- 至少覆盖统计、流程、关系、矩阵、证据论证五个图形家族；每个家族都有正向测试和至少一个前提不满足的负向测试。
- 论文案例实际生成的图形组合至少包含五种不同视觉家族；不得以多个相似树图或重复四面板图满足数量。
- 生成结果中至少出现：一张流程图、一张真实统计图、一张关系图、一张矩阵/正式表格图和一张证据论证图；每张图均可回到来源、数据 artifact 或执行记录。
- 对缺失二维矩阵、缺失时间字段、无因果证据、无真实阶段和无成对估计等情况，系统返回结构化拒绝/降级原因，不生成伪图。
- Word/PDF 真实渲染无裁切、重叠、题注错位和不可读标签；PPT 真实文件检查无乱码、溢出、线条穿字和小图缩略化。
- 现有 `pptxforge` 组件得到复用，不新增运行时依赖，不改变 API、数据库、LLM Gateway、Worker 和产品边界。
