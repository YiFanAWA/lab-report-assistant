# SPEC 0043 当前论文质量审查

**审查日期：** 2026-08-14  
**审查对象：** `server/dev-docs/e2e-screenshots/spec0035_paper_review/spec0043_publication.docx`  
**对照真源：** `dev-docs/specs/0043-publication-grade-manuscript-and-defense-system.md`、`dev-docs/acceptance.md`  
**审查性质：** 内部质量审查，不代表 SPEC 0043 已收口，也不代表该成品可以直接投稿或作为学校正式模板终稿。

## 一、结论先行

当前论文已经明显超过“套 Word 模板的技术验收报告”，可以称为一份**证据链清楚、数据口径诚实、具有教学复核边界的论文解读与描述性分析成品**。它的工程交付基础是比较好的：有真实公开数据、有原论文与本地数据口径区分、有结果表和图、有观察性研究边界，也已经使用了 Word 的动态目录、图表编号和交叉引用字段。

但它目前还不能被称为“可直接投稿的学术论文”或“毕业论文终稿”。核心原因不是字体、颜色或图表数量，而是学术论证的深度、方法可复现的完整度、文献对话范围和成品正文的读者视角仍未完全收口。

当前判断如下：

| 维度 | 判断 | 说明 |
| --- | --- | --- |
| 数据与证据链 | 较强 | 101,766 条原始记录、17,018 条 HbA1c 检测记录、69,984 条原论文最终样本被明确区分；没有把本地数据伪装成原论文完整复现。 |
| 结构与交付工程 | 较强 | 已有摘要、目录、五章结构、参考文献、附录；DOCX 中存在 TOC、SEQ、REF、PAGEREF 字段；Word COM 已能导出 26 页 PDF。 |
| 统计方法呈现 | 中等 | 已有风险、风险差、Wilson 95% CI、分层和简化 Logistic，但模型编码、队列口径、诊断和敏感性分析仍不够完整。 |
| 学术论证与贡献 | 中等偏弱 | 当前主线是“原论文解读 + 公开数据的教学性描述性复核”，研究贡献和与相关研究的比较还不足以支撑投稿级主张。 |
| 正文专业性 | 未收口 | 内部工程追溯字段仍出现在正文，削弱了论文的读者视角，并直接偏离 SPEC 0043 的正文/附录边界。 |

一句话判断：**现在适合定位为“高质量教学性论文解读与数据分析报告原型”，还不适合包装成“已经可以直接投稿的论文”。**

## 二、已经做得好的地方

### 1. 研究对象和数据口径没有被混写

正文明确区分了原论文使用的 Cerner Health Facts 队列、本地公开 UCI CSV 和原论文最终样本。摘要和方法中同时给出了 101,766、17,018、69,984 等关键数字，并解释这些数字不属于同一条可直接替换的分析队列。这是当前成品最重要的可信度来源。

### 2. 已经建立了观察性研究的解释边界

正文多处明确说明 HbA1c 检测状态与再入院之间是观察性关联，不能直接解释为检测行为造成风险下降，也不能把简化模型称为原论文完整模型。这避免了医学内容中最危险的因果过度推断，也符合项目“不提供诊断或治疗建议”的产品边界。

### 3. 结果不再只有一句结论

当前成品至少形成了以下结果链：分组再入院率、风险差与区间、年龄分层、住院天数分层、字段缺失结构、原论文与本地口径比较、简化多变量 Logistic 复核。图、表、说明和限制之间已经有了比早期版本更完整的对应关系。

### 4. 文档交付链已经有真实基础

本次结构复核确认：DOCX 有 172 个段落节点、4 个表格、13 个内嵌图形、3 个 section；OOXML 中存在动态 TOC、SEQ Figure/Table、REF 和 PAGEREF 字段。当前 DOCX 经 Word COM 成功导出为 26 页 PDF，说明“最终 DOCX 作为 PDF 唯一来源”的技术方向是可行的。

## 三、当前必须收口的问题

以下问题按“阻断当前论文称为出版级成品”的标准分级，而不是按是否影响当前教学演示分级。

### P0：正文仍混入工程追溯字段，违反 SPEC 0043 的正文边界

这是当前最明确的合同级问题。

结构审查发现，正文段落中仍有 31 个 `Artifact Source` 段落、9 个 `Figure Lead` 段落，以及大量“主张 / 方法 / 结果 / 边界”“stages -> nodes -> transitions”“CHART_PNG”等内部生产语义。它们出现在图表附近和方法章节中，而不是只存在于附录、manifest 或 speaker notes。

SPEC 0043 已明确要求：工程追溯信息移入附录、文档属性、manifest 或 notes，正文只保留论文读者需要的来源、方法、样本量、统计口径和解释边界。当前输出虽然“可追溯”，但追溯方式仍像内部验收报告，破坏了正式论文的阅读连续性。

**处理要求：**

- 正文保留自然语言的来源、样本、方法、结果和限制说明；
- `Artifact Source`、内部资产类型、生产阶段、图表生成类型、主张模板等移至附录或交付 manifest；
- `Figure Lead` 若保留，必须改写为面向读者的结果引导段，不能出现内部模板字段或流水线术语；
- 重新生成 DOCX/PDF，并逐页确认正文不再暴露内部生产字段。

### P1：论文的“贡献”仍更像教学目标，不像研究贡献

当前论文的核心价值是解释原论文、区分分析队列、用公开数据做方向性复核。这对于课程实验或论文阅读报告是合理的，但如果标题和语气继续使用“正式学术论文”定位，读者会追问：

- 本文相对于原论文或相关研究新增了什么知识？
- 是方法复核、数据质量审计、外部可迁移性分析，还是教学性再分析？
- 为什么选择这些分层变量和简化模型？
- 哪些结果是预先设定的，哪些是探索性发现？

目前正文对“做了什么”解释得比“为什么值得作为一篇独立论文发表”更充分。因此应明确选择一种定位：

1. 保持教学性论文解读与描述性复核定位，并降低“可投稿论文”的外部表述；或
2. 增加明确的研究空白、贡献声明、相关研究比较、预先分析计划和新增分析，使其成为真正的独立研究稿件。

推荐第一种作为当前产品 V1 的诚实定位，第二种应作为后续研究型模板，而不是靠润色现有文字完成。

### P1：方法可复现信息仍不足以让第三方无歧义重跑

当前方法章节已经给出变量方向和分析步骤，但仍需补齐以下可执行细节：

- 从 101,766 条公开记录到各个分析子集的逐步保留/排除数量与规则；
- HbA1c 检测状态、30 天再入院结局、`<30`、`>30`、`NO` 等原始编码的精确定义；
- Logistic 模型中各协变量的编码、连续变量处理、缺失处理、参考组和纳入规则；
- 模型样本量、事件数、拟合诊断、区间计算实现和软件/包版本；
- 分层分析是否预先指定、是否存在多重比较，以及结果对关键口径变化是否稳定；
- 原论文 69,984 条最终样本的筛选过程哪些可从公开资料核对，哪些只能作为原论文报告值引用。

当前文字已经诚实地说“不是完整复现”，但“不是完整复现”不能替代本地复核自身的方法合同。第三方应能仅凭论文和附录重建本地分析，而不是依赖工程目录中的隐含脚本。

### P1：统计解释边界有了，但稳健性证据还不够

风险差、Wilson 区间和简化 Logistic 是好的起点，但出版级稿件还需要说明：

- 观察到的差异是否可能由检测选择、病情复杂度、医疗关注度、医院差异和缺失机制造成；
- 简化 Logistic 的效应是否对协变量选择和编码敏感；
- 是否进行基本敏感性分析或至少明确为什么不做；
- 是否避免把很小的 P 值写成临床重要性；
- 是否区分统计显著、效应大小、区间宽度和外部可推广性。

这不是要求项目 V1 伪装成临床研究，而是要求论文明确“本地分析能证明到哪一步”。如果没有稳健性分析，正文应更明确地把结果定位为描述性证据，而不是可用于决策的效应估计。

### P1：参考文献范围过窄，尚未形成充分的学术对话

当前参考文献只有原论文和 UCI 数据集。它们足以支撑“来源与数据集”说明，但不足以支撑投稿级的研究背景、方法选择和讨论。

至少需要根据真实可核验来源补齐：原论文相关研究背景、观察性研究报告规范或统计方法依据、数据集使用背景，以及与 HbA1c 检测、再入院和缺失机制相关的必要文献。不能为了增加数量而生成无法核验的引用；如果本轮没有真实来源，就应保持“教学性论文解读”的定位，不伪装成完整综述。

### P2：结果与讨论的学术密度仍不均衡

结果章节的图表数量和追溯说明已经较多，但讨论章节目前主要由两段变量关系解释和两段局限性说明构成，缺少以下内容：

- 与原论文结果及相关研究的逐项比较；
- 为什么公开数据与原论文样本会产生口径差异；
- 结果对数据质量、医院行为和选择机制的具体含义；
- 哪些观察结果可迁移，哪些只能在本数据集内成立；
- 教学分析对后续研究设计的可操作建议。

如果不增加真实证据，不能用泛化段落填满篇幅。更好的做法是增加少量有证据支撑的讨论，或明确缩短论文并保持“教学性复核报告”定位。

## 四、交付与验收风险

### 1. 当前 PDF 已验证“能导出”，但没有完成本环境下的逐页视觉收口

本次使用 Word COM 从当前 DOCX 成功导出 26 页 PDF，证明转换链可用。但标准 DOCX 渲染脚本因环境中缺少 LibreOffice/`soffice` 无法运行，PDF 页面图像虽然已经生成，当前环境的图像查看器又受 Windows ACL 限制，未能完成逐页人工视觉确认。因此本审查不能声称当前 PDF 已通过“无裁切、无重叠、图注位置、表格分页、字体可读性”的完整视觉门禁。

这属于当前交付的验收风险，不等于已确认存在全部排版缺陷。正式收口前必须在可视化环境中完成逐页检查，并记录真实截图或等价证据。

### 2. 当前审查工作区的全量测试仍有与成品 fixture 相关的失败

此前全量后端测试记录为 1231 passed、2 failures，失败原因是当前工作区缺失 `spec0035_paper_review/spec0035_paper_review.docx` 与 `publication_manifest.json` 等 fixture，而不是本次论文文本本身的统计结论。它们仍然阻止“全量门禁已通过”的表述。完成论文收口前，应补齐或明确移除过期 fixture，并重新运行全量后端、Alembic、前端 lint/build 和文档同步检查。

### 3. 学校或期刊专用格式没有被证明

项目当前只实现通用 `zh_academic_thesis` profile，不声称满足某一所学校、学院或期刊的专用模板。这是已经确认的产品边界，不应被写成缺陷；但面对用户时必须明确说明：最终提交前仍需按目标单位的封面、页眉页脚、参考文献格式、目录规则和装订要求做适配。

## 五、推荐的下一步收口顺序

1. 先处理 P0：把工程追溯移出正文，重新生成最终 DOCX/PDF。
2. 做一次“学术内容审计”：研究问题、目标、贡献、队列口径、变量定义、模型规格、稳健性、讨论和引用逐项对照证据。
3. 确认产品定位是“教学性论文解读与描述性复核”还是“独立研究稿件”，并统一标题、摘要、结论和对外说明。
4. 在有真实来源的前提下补齐相关文献；没有来源就不扩写成伪综述。
5. 在真实 Word/PDF 环境逐页验收，并补齐当前缺失 fixture 后重跑全量门禁。
6. 论文质量门禁通过后，再推进“安装包 + 本地 MCP”作为交付渠道；MCP 不能成为掩盖论文内容不足的包装层。

## 六、收口标准

只有同时满足以下条件，才能把这份成品称为“SPEC 0043 论文交付收口”：

- 正文不再出现工程资产类型、生产阶段和 manifest 语义；
- 研究问题、分析队列、变量、模型和结果可以由第三方按论文与附录复核；
- 论文明确自己的教学性复核边界，不把观察性关联包装为因果结论；
- 参考文献和讨论足以支撑当前对外定位；
- DOCX 是唯一排版真源，PDF 由最终 DOCX 导出；
- DOCX/PDF 完成逐页视觉检查，PPT 与论文共享事实但不压缩成低可读性页面；
- 当前全量测试、迁移、前端构建和文档索引全部有本轮证据；
- 项目负责人查看真实成品并确认视觉效果。
